## 1. 現在の状態

- 開発言語はKotlin Native Androidです。
- フェーズ1のコア層についてCodexレビュー改修済みです。
- 単体テスト15件、`assembleDebug`、`lintDebug`は成功済みです。
- Codex判定は「コア層のみ条件付き統合可能」です。
- フェーズ1全体および`main`への統合はまだ禁止です。
- 日本語を含むパスではGradle 8.2.1のテストクラスパス問題が発生する場合があります。
  必要なら英数字だけの一時ジャンクションまたは作業コピーから検証してください。

## 2. 変更してはいけない安全仕様

- 健康・安全または不可逆損失に関わるToDoは、固定Lowより常に優先する。
- 同一操作IDの成功済み処理を二重実行しない。
- Undoに失敗したコマンドをUndoスタックから失わない。
- DB鍵とAPIキーをソース、ログ、例外、画面へ出さない。
- Keystore鍵が失われた場合、新しい鍵で既存暗号文を上書きしない。
- OpenAI APIのエラー本文、Authorizationヘッダー、会話本文をログやUIエラーへ出さない。
- OpenAI API要求では`store=false`を維持する。
- `safety_identifier`へメールアドレス、氏名、端末IDなどの個人情報を直接入れない。
- API成功を確認する前に「登録・変更・削除しました」と表示しない。
- 支払い、購入、契約、メッセージ送信、服薬変更、本人の許可がない外部連絡を実装しない。
- 正常なCodex改修部分を理由なく全面的に書き換えない。

## 3. 今回実装する範囲

フェーズ1の残存Highリスクを、小さな単位で次の順に対応してください。

### 優先1：永続的な操作履歴とUndo/Redo

- `OperationHistory`を暗号化Room DBへ保存する。
- Command実行と操作履歴保存を同じDBトランザクションで扱う。
- アプリ再起動後も取り消し可能な操作を復元する。
- Undo/Redoの成功・失敗・部分成功を記録する。
- Undo失敗時は元データとスタックを保持する。
- 複数ステップ操作は、途中失敗時の補償処理を定義する。
- 同一操作IDの再試行で二重登録しない。

### 優先2：暗号化DB・鍵管理の実機統合試験

- SQLCipher DBが平文SQLiteとして読めないことを確認する。
- アプリ再起動後に同じDBを復号できることを確認する。
- 暗号化パスフレーズ、Keystore鍵、保存暗号文をログへ出さない。
- 保存暗号文破損時に既存データを上書きしない。
- Keystore鍵消失時に安全な復旧エラーを表示する。
- OSバックアップと端末間転送からDB・APIキーが除外されることを確認する。
- `@Upsert`がSQLCipher環境で既存ToDoを安全に更新できることを確認する。

### 優先3：構造化AI操作

- OpenAI Responses APIのStructured Outputsまたは厳格なJSON Schemaを使用する。
- 最初はToDo作成候補だけに限定する。
- AI出力を直接DBへ保存せず、検証済みCommandへ変換する。
- 未知フィールド、未知操作、壊れたJSON、空タイトル、異常日時を拒否する。
- 自動実行可能・確認必須・禁止操作をコード上のポリシーとして分離する。
- API応答だけを外部操作成功の根拠にしない。
- 操作IDを要求から履歴保存まで引き継ぐ。
- 自動再試行は行わない。将来追加する場合も回数制限と同一操作IDを必須とする。

### 優先4：本番アラーム統合

- `poc_kotlin`の実装をそのままコピーせず、本番DB・操作履歴・Undoと統合する。
- UUIDをアラームの不変IDとして使用する。
- Exact Alarm権限、通知権限、Doze、再起動、アプリ更新後復旧を扱う。
- 予約成功後だけ成功表示する。
- 保存失敗時はOS予約を補償取消する。
- 発火済み・期限切れ予約を再登録しない。
- 同名アラームを独立して登録・取消できるようにする。

一度に優先1～4をすべて実装しないでください。まず優先1だけを完成させ、テスト結果を報告してください。

## 4. OpenAIモデルに関する制約

- 現在の既定モデル`gpt-4o-mini`を、独断で高価格モデルへ変更しないでください。
- モデル変更を提案する場合は、品質、費用、速度、構造化出力対応を比較してください。
- Chat Completions APIへ戻さず、Responses APIを維持してください。
- APIキーをアプリ外へ出したり、サンプル値をAPIキー形式でソースへ直書きしたりしないでください。

## 6. 必須テスト

最低限、今回の優先1では以下を追加してください。

- Command成功と履歴保存が同時に成立する。
- Command失敗時に成功履歴を残さない。
- 履歴保存失敗時に対象データだけが変更されない。
- 同一操作IDを2回実行してもデータが1件だけ作られる。
- Undo成功後にデータと履歴が一致する。
- Undo失敗時に元データとUndo可能状態が残る。
- Redo成功・失敗時の整合性。
- アプリ再起動相当の再生成後にUndo可能操作を復元できる。
- 複数操作の逆順Undo。
- 不明・破損した履歴JSONを実行せず安全に失敗する。

既存の15単体テストもすべて維持してください。

実行コマンド:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

日本語パス問題が出た場合は、英数字パス経由で同じコマンドを実行し、その事実を報告してください。

## 7. 完成条件

- 今回選んだ1機能だけが実装・テスト済みである。
- Critical・Highの新しい既知不具合がない。
- 既存15テストと追加テストが成功する。
- Android Lintに新しいErrorがない。
- Debug APKを生成できる。
- APIキー、暗号鍵、会話本文、健康・服薬・家計情報がログやテスト成果物へ含まれない。
- `docs/TASKS.md`、`docs/TEST_PLAN.md`、`docs/CHANGELOG.md`を実績どおり更新する。
